# ADR 0011: Offline Synthetic Surface Candidate Quarantine

**Status:** Accepted for surface quarantine foundation | **Date:** 2026-07-19

## Context

ADR 0010 leaves every Mars and Moon product requirement reference-only until exact product selection, asset-level rights, scientific validation, runtime verification, and capture placement pass their own gates. That is the correct publication boundary, but it did not provide a surface-specific way to exercise candidate identity, primary-data/source-label pairing, immutable quarantine, exact-byte replay, and label inspection without contacting an archive or pretending that fixture bytes were real products.

The generic connector runner already demonstrates quarantine-first execution for bounded responses. Surface candidates add product-specific relationships: an unreviewed exact identity must remain bound to its `ReferenceOnlySurfaceProduct`, primary data and source labels must be reciprocal, cartographic candidates need a separate projection definition, and an injected label inspector must return the exact proposal/file context. This checkpoint must test those mechanics offline without weakening either the connector or surface-provenance gates.

## Decision

- `createSurfaceQuarantineProposal` produces a deeply frozen `unreviewed-offline-surface-candidate` marked `fixtureContractOnly: true`. It retains the complete parsed reference record, its canonical SHA-256, one exact candidate identity, exact artifact descriptors, code-owned limits, and a canonical proposal SHA-256. If the reference already identifies an exact record, the candidate identity must match it. A selection-pending reference may name a candidate for offline inspection, but that proposal is not a reviewed selection.
- Candidate artifact descriptors bind an opaque artifact ID, role, extraction-safe filename, credential-free query-free HTTPS source URL, media type, positive byte length, SHA-256, and reciprocal pairing IDs. The URL is frozen metadata and is not dereferenced by this module. IDs, case-insensitive filenames, and URLs are unique. Primary data and source labels must exist and pair reciprocally; orthomosaics, elevation models, and confidence masks require exactly one projection-definition artifact.
- The schema rejects traversal-like and reserved basenames, mutable aliases, and its enumerated archive/compressed and executable/script filename suffixes. Candidate URLs must use default-port HTTPS without credentials, query parameters, or fragments and must name the exact filename. The executor rejects the policy's enumerated archive and compressed-container signatures even when the filename or media type attempts to disguise them; this is a bounded fixture screen, not general archive, executable, or malware detection.
- The proposal freezes at most 16 artifacts. A source-label or metadata artifact is limited to 4 MiB, any other single artifact to 16 MiB, and the entire candidate to 32 MiB. These are small-fixture limits, not production terrain or media budgets.
- `quarantineAndInspectSurfaceCandidate` accepts only injected source, store, reader, parser, and clock dependencies. This checkpoint ships no live source implementation, network transport, credential path, or ambient `fetch` call; only synthetic fixture implementations are authorized. The module itself performs no ambient network fetch. Every injected dependency is a trusted fixture boundary and can lie or collude, so its output does not attest source authenticity, dependency provenance, storage immutability, replay independence, parser independence, or elapsed real time. Replacing any dependency with a downloader or production service is outside this decision.
- The current executor receives one complete `Uint8Array` per artifact, checks its exact frozen length and SHA-256, applies the enumerated signature screen, and writes it artifact-by-artifact with conditional-create semantics below `quarantine/surface/`. It then asks the injected reader for every object and rechecks its length, hash, and signature policy before label inspection. An object's `immutable: true` field is a claim made by the injected store and validated structurally; the module cannot independently prove that storage is immutable. This is bounded whole-file fixture handling, not a streaming, resumable, compressed, archive, or bulk-product pipeline.
- Each capture receipt binds the proposal and reference checksums, artifact identity, filename, role, media type, exact byte length and digest, capture time, claimed-immutable quarantine object, and its own canonical checksum. Store responses with a different key, type, length, digest, namespace, or immutability state fail.
- For every source label, an injected parser receives the bytes returned by the injected reader after the executor's replay checks and an expected binding containing the proposal/reference hashes, exact candidate identity, body, product kind, source release, label identity, and complete captured-file inventory. Its strict payload also binds parser ID, semantic version, code commit, asserted inspection checks, and a canonical payload checksum. The executor verifies that payload against the expected binding. Within the trusted fixture dependencies, this binds the returned replay and parser assertion to the same contract context; it does not prove independent replay or parsing and is not a production PDS/USGS parser, scientific correctness finding, malware verdict, or rights decision.
- A successful run returns `machine-inspected-needs-selection-and-rights-review`, with hash-bound capture receipts and label-inspection payloads. Proposals, receipts, and reports remain `fixtureContractOnly: true` and keep `selectionReviewed`, `selectionAuthorized`, `artifactVerificationAllowed`, `rightsReviewed`, `scientificValidationPassed`, `scienceValidated`, `runtimeUseAllowed`, `renderAllowed`, `capturePlacementAllowed`, `releaseEligible`, `publicationAllowed`, `activationAllowed`, `sourceAuthenticityVerified`, `dependencyProvenanceAttested`, and `ambientNetworkFetchPerformedByModule` false. The last flag describes only this module, not what a malicious injected dependency may do. No output is a reviewed-selection capability, frozen surface-product manifest, runtime token, render token, capture pose, release candidate, signature, or active-release pointer.
- The underlying Mars and Moon ledgers are unchanged. Their `assetBytesPresent`, `renderAllowed`, and `releaseEligible` fields remain false, and their six capture contexts remain withheld.

## Consequences

The project can now test one deterministic surface-specific contract—reference requirement → unreviewed candidate → synthetic exact bytes → claimed-immutable quarantine → injected replay → bound label inspection—without the module downloading or admitting a source product. Its schemas and hashes bind the internally represented fixture context and bytes and detect inconsistent substitutions. Because all operational dependencies are trusted and may collude, they prove internal consistency only; they do not prove that the claimed source, write, replay, parse, or time event occurred independently, nor scientific truth, rights, source authenticity, dependency provenance, or release readiness.

The module never promotes or persists rejected or unreviewed material outside the quarantine namespace; injected dependencies remain outside that guarantee. A structurally valid report still requires separately authorized exact-product selection, real source acquisition, asset-level rights review, source-specific scientific parsing and validation, reviewed frozen-manifest construction, runtime verification, pose validation, capture-placement review, and release governance.

Real terrain, imagery, labels, meshes, calibration products, panoramas, and orbital-context products remain blocked. A future source-backed path needs a separately reviewed transport and admission policy; bounded streaming rather than whole-file memory; interruption, retry, and conditional-write recovery; content-length and compression handling; archive/media/parser sandboxes; source-specific label and projection parsers; larger product budgets; and independent scientific and rights review. This decision neither authorizes bulk ingestion nor changes ADR 0006's production-transport restrictions.

Nothing in this checkpoint completes Stage 4, Stage 6, or the product. It creates no hosted resource, source request, download, public asset, publication, activation, or deployment.

## Validation

Local validation passed on 2026-07-19. `npx tsx --test tests/surface-quarantine.test.ts` passed all 16 focused tests. `npm run check` passed connector typechecking, all 71 connector tests, and verification of four deterministic frozen-manifest examples.

The focused suite covers deterministic deeply frozen proposals and code-unit ordering; exact-reference substitution rejection and selection-pending non-authority; URL, filename, media/extension, reciprocal-pairing, projection, per-artifact, label, and aggregate-limit failures; and the successful synthetic exact-byte quarantine, replay, label-binding, receipt, and report path with zero ambient `fetch` calls by the module. It also confirms runtime rejection for the reference, report, and their structural copies. Its adversarial cases reject every enumerated archive signature before persistence; canonical URL and quarantine-object-key traversal, control, separator, and casing violations; source length/hash drift; drifted store claims; immutable-key collisions; same-length replay drift, including the clone-before-hash regression; parser-context drift; injected parser rejection propagation; noncausal capture order and final-inspection chronology; duplicate, reordered, or wrong-label file bindings; missing or duplicate captures and duplicate label inspections; mixed parser implementations; report reordering; authority laundering; and proposal/report rewrites even after recomputing their outer checksums.

These results validate only the synthetic `fixtureContractOnly` contract with trusted injected source/store/reader/parser/clock dependencies and literal-false authority fields. They do not validate a live source fetch or download, real product bytes or selection, independent source authenticity or dependency provenance, actual storage immutability, a production parser or transport, rights, scientific correctness, runtime or render use, capture placement, release, publication, activation, or deployment; no reference-ledger gate advances.
