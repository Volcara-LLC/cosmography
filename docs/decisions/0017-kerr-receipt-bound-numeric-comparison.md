# ADR 0017: One-Use Receipt-Bound Kerr Numeric Comparison

**Status:** Accepted for package-only numeric-comparison foundation | **Date:** 2026-07-19

## Context

ADR 0016 ends with one exact process-issued preparation capability backed by a private, receipt-bound candidate. That candidate preserves the runner-normalized numerics and attaches full-plan identities only after the answer-blinded mapping-review decision is accepted. It cannot enter the legacy caller-declared comparison path, and the public preparation deliberately contains neither candidate numerics nor reference outcomes.

The next boundary must compare that private candidate with the already frozen reference plan exactly once. It must preserve disagreement and unresolved results, avoid inventing a tolerance for camera coordinates that were intentionally withheld from a camera-and-solver run, and emit evidence for later scientific review without turning numeric proximity into mapping correctness, implementation independence, scientific validation, render authority, or release authority.

## Decision

- The consumer accepts only the exact process-issued preparation object and one canonical comparison time. Structural copies, admissions, verified receipts, legacy candidates, and serialized lookalikes are rejected. Exact raw, normalized, and mapping-signature bytes remain detached private copies rather than caller-resupplied inputs. Before consumption, integrity replay byte-compares the retained raw and normalized copies with the independent admission context, rehashes those bytes against the admission bindings, replays the mapping decision and verifier receipt against the retained signature bytes, regenerates the private candidate bytes, and rechecks the exact bundle, plan, subject, decision, reviewer separation, row associations, chronology, identities, and checksums.
- One preparation can attempt numeric comparison once. All caller-controlled input and private capability checks complete before the burn. A second attempt check immediately adjacent to the burn closes reentrancy through caller-owned proxy descriptors or mutable host operations. The capability is burned before the synchronous comparison kernel runs; an arithmetic or invariant failure after that boundary is permanent, and no partial result is issued. There is no callback, promise, or external operation inside the consumed boundary.
- Deterministic numeric arithmetic lives in an internal package module that is not exported as a package subpath. The legacy comparator and receipt-bound consumer share seed, endpoint, tolerance, disposition, reason-ordering, and aggregate-summary math. The mathematically bounded unit-sphere chord is clamped to `2` only when independent IEEE-754 trigonometric rounding overshoots that exact maximum by a few ulps, so a valid antipodal disagreement cannot become a post-burn schema failure. Existing legacy outputs remain unchanged for their prior exact-screen cases; the receipt-bound candidate is never fabricated as a legacy candidate or passed through the legacy comparator.
- Integrator-only comparison treats screen coordinates as exact supplied inputs and fails closed if they change. Camera-and-solver comparison retains the distinct reference and runner screen coordinates plus exact deltas. Because no screen tolerance was frozen before execution, a screen mismatch cannot be called within tolerance and no post-run threshold is invented. It downgrades an otherwise passing row to `inconclusive` with `camera-screen-coordinate-delta-not-adjudicated`; stronger seed incompatibility, endpoint disagreement, termination disagreement, or unresolved outcomes remain visible rather than being sanitized.
- Every result row retains the exact runner screen coordinates, initial normalized momentum, conserved quantities, termination, and endpoint from the private prepared candidate. It also binds the preparation, admission, plan, mapping decision, candidate, prepared row, blinded source row, case, request, report, reference ray, pixel, comparison scope, numeric deltas, flags, disposition, ordered reasons, and a distinct row identity/checksum. The package never substitutes reference outcome values into the candidate-numeric field; integrator-only seeds may already equal reference inputs because that scope intentionally supplied those inputs to the runner.
- The aggregate record binds the exact preparation and candidate, opaque ordered reference associations, frozen provisional tolerances, all row checksums and diagnostics, disposition counts, screen mismatch counts, maxima, RMS endpoint chord, and aggregate numeric agreement. Coordinate-time and energy-times-affine-parameter deltas are retained as diagnostics but have no pre-registered tolerance and do not participate in aggregate agreement. The result has a separate 4 MiB canonical-output ceiling because the generated diagnostic record is larger than the bounded 3 MiB private candidate. Checksums detect accidental substitution but authenticate nothing.
- A successful comparison is deeply frozen, branded by exact object identity, and retained with its preparation, private candidate, plan, bundle, and evidence context for a future scientific-review gate. Structural copies may be inspected as non-authoritative data but cannot cross that future capability boundary. Self-integrity and exact private-context replay are distinct checks.
- `comparedAt` is a caller-declared canonical timestamp. The package checks its ordering against the retained declared preparation, decision-expiry, and execution-claim-expiry timestamps, but it has no authoritative clock and does not authenticate actual wall time. `comparisonExecuted` and `numericComparisonExecuted` are true only as narrow process facts. The record keeps injected reviewer and runner authentication, real external execution, implementation provenance, independence, mapping correctness, scientific validation, independent validation, rendering, production use, placeholder replacement, release eligibility, publication, and activation false. `independentReference` remains `not-run`, and provisional tolerance agreement is explicitly not validation.
- This package still performs no filesystem or network I/O, acquisition, archive extraction, build, shell, process, worker, native loading, sandbox operation, signing, output capture, or external execution. Tests use synthetic in-memory capabilities and same-project reference data. No real external implementation, output, mapping review, numeric comparison, or scientific conclusion exists.

## Consequences

Cosmography now has a fail-closed package path from one exact receipt-bound preparation to one deterministic numeric-comparison record without exposing the private candidate as a caller-controlled legacy artifact. Numeric disagreements, unresolved rows, convention incompatibilities, and unadjudicated camera coordinates survive as review evidence. Successful output remains process-local and cannot authorize the Black-hole Lab renderer.

This is not independent validation. A production system still needs authenticated reviewer and runner identities, an authoritative clock and revocation registry, a durable signed ledger, immutable evidence retention, cross-process atomic consumption, verified source-to-executable and normalizer lineage, and an isolated reproducible runner. The next package gate is independent scientific adjudication of the exact issued comparison. GPU/WebGL parity, emission and radiative transfer, image generation, named-device performance, accessibility, release review, and replacement of the procedural placeholder remain later gates. Nothing here completes BH1, a roadmap stage, or the product.

## Validation

Acceptance requires strict tests for exact-reference agreement, disagreement and unresolved preservation, numeric parity with the legacy oracle, exact runner-numeric retention, camera-screen mismatch handling without an invented tolerance, preparation and plan substitution, structural copies, chronology, replay and synchronous concurrency, proxy reentrancy, permanent burn after an unsafe winding-delta failure, row and aggregate integrity replay, deep freezing, static no-I/O imports, the generated-output byte ceiling, and literal-false scientific, render, production, release, publication, and activation authority.

Those tests validate only the bounded local protocol and deterministic arithmetic. They cannot establish the origin, licensing, independence, execution, mapping correctness, scientific quality, or renderer fitness of any real external Kerr implementation or output.

The accepted checkpoint passes the complete relativity package check with 112 tests. Its focused receipt/admission/mapping/comparison lifecycle suite passes all 32 cases, including nine receipt-bound consumer cases, while the refactored legacy comparison suite remains 21-for-21. TypeScript compilation, antipodal-rounding regression, and the static no-I/O import audit also pass.
