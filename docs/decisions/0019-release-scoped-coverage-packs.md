# ADR 0019: Release-Scoped Evidence Coverage Packs

**Status:** Accepted for Coverage Pack v1 foundation | **Date:** 2026-07-19

## Context

Cosmography's Voyager 1, Mars/Jezero, Apollo 17, and Earth-network experiences already retain useful but different evidence records. Voyager has frozen public-reference metadata, a retained Horizons fixture, and proposed kernel filenames without admitted kernel or media bytes. Mars and the Moon have reference-only product ledgers and withheld capture contexts without admitted surface artifacts, runtime tokens, solved poses, or physical frustums. Earth has a representative international registry and an explicit gap ledger that disclaims exhaustive coverage. The pages expose some of these limits, but their local readiness summaries are not one reusable, release-bound contract.

The roadmap requires every body or mission to show geometry, terrain, observations, media, timeline completeness, update cadence, rights, and validation tier. A generic card cannot honestly infer a completion percentage because these records do not define a defensible global denominator. It also cannot become a mutable annotation attached to an otherwise immutable release: changing a coverage judgment in place would make historic release URLs appear to say something they did not originally bind.

## Decision

- Coverage Pack v1 is a generic scientific-model contract, while the four initial records remain web adapters over existing frozen domain exports. The contract has exactly eight ordered dimensions: `geometry`, `terrain`, `observations`, `media`, `timeline-completeness`, `update-cadence`, `rights`, and `validation-tier`.
- Dimension state is deliberately qualitative and bounded to `out-of-scope`, `absent`, `reference-records-only`, `frozen-records-only`, or `validated-artifact-evidence`. The final literal is reserved and rejected by v1 because the contract does not yet bind an authenticated artifact-validation receipt; no current pack may display it. Counts state only what an exact source record supports. Packs publish no percentage, coverage score, inferred global denominator, or silent interpolation.
- Every pack binds one exact source release, its content and manifest SHA-256 values, and canonical source-record bindings that name a repository-relative module, export, version, digest, and optional byte length. The scoped subject must resolve through the same bound record and reference union. Absolute paths, traversal, backslashes, URL-like paths, mutable branch/channel aliases, duplicate bindings, digest drift, and dangling or non-reciprocal dimension/gap/requirement references fail closed.
- Pack identity, correction pointers, canonical JSON, SHA-256, and strong ETag are deterministic. A correction cannot mutate a pack within the same immutable release; a superseding revision belongs to a distinct exact release and binds the preceding release and pack digest. Standalone serialized fields are only a cryptographic predecessor declaration, not proof that the predecessor exists. Creation and serving of a correction must load both exact packs and pass the pair verifier, which enforces consecutive revisions, stable identity/scope, causal issuance, the exact predecessor tuple, and a derived—not caller-selected—set of affected dimensions. The current web v1 resolver has no historical predecessor loader, so it rejects every superseding correction before manifest comparison instead of serving an unverified declaration.
- A separate pinned coverage manifest indexes exactly the four current pack identities and digests while binding the existing foundation release and bundle. It explicitly records that the projection is not part of the already-frozen navigation release content. The manifest identity is SHA-256 over the complete strict parsed manifest under the explicit `cosmography-foundation-coverage-manifest-stable-json-v1` canonicalization; whitespace and key order are non-semantic, while any semantic warning, authority, release, set, or pack-pin drift rejects. The existing release manifest, navigation bundle digest, and D1 fixture are not rewritten to retroactively include it.
- Exact-release API routes expose the index and individual packs only under `/api/v1/releases/{releaseId}/coverage`. There is no mutable `latest` alias. Malformed identifiers, unknown releases or packs, query parameters, unsupported mutation methods, and integrity drift fail closed; errors are not cacheable. `HEAD` preserves the GET validators without a body, `OPTIONS` advertises the read-only surface, and unsupported methods return `405` with `Allow: GET, HEAD, OPTIONS`. Successful wrappers use representation-safe HTTP ETags/content digests and expose the distinct canonical pack/set ETag and SHA-256 values in coverage headers and bodies.
- One accessible evidence card renders the canonical pack on Voyager, Mars, Apollo 17, and Earth. The card visibly states that the projection is non-authoritative and release-ineligible, uses textual rather than color-only states, preserves the eight-dimension order, exposes exact source bindings, gaps, next-evidence requirements, correction lineage, and API identity through native disclosures, and makes no completeness percentage claim.
- A Coverage Pack is descriptive evidence inventory only. Its serialized authority flags remain false for completeness, scientific or independent validation, rights clearance, rendering, release, publication, and activation. It cannot admit assets, issue runtime capabilities, clear rights, solve geometry, fill gaps, promote a release, or authorize publication.

## Consequences

The four initial experiences can use one truthful comparison vocabulary without flattening their domain-specific records or duplicating local readiness arithmetic. API consumers can pin the exact coverage projection they inspected, and future corrections remain auditable across immutable release identities.

The coverage projection does not make the foundation atlas complete. It does not add a kernel, media byte, terrain product, camera pose, site, source, or scientific result. Existing Voyager, surface, Earth, release-governance, and Kerr gates remain unchanged. Future packs must bind new exact releases when source facts or judgments change; live freshness, acquisition, validation, signing, activation, and deployment remain separate governed work.

## Validation

Scientific-model tests pin canonical dimension order and labels, safe source bindings, exact reciprocal references, correction lineage across distinct releases, digest and ETag derivation, deep immutability, strict parsing, and literal-false authority. Web data tests bind the four adapters to their frozen exports, recompute the canonical semantic manifest digest, reject non-index semantic drift, and reject standalone corrections. Built-worker tests cover exact-release list/detail responses, representation and canonical digests/ETags, conditional GET and HEAD requests, OPTIONS, explicit read-only method rejection, no-store errors, malformed and unknown identifiers, mutable-alias rejection, query rejection, and integrity failure. Rendered-HTML and visual checks cover all four cards, semantic labeling, native disclosures, visible boundary language, canonical dimension order, exact-release links, keyboard/focus behavior, narrow layouts, forced colors, and the absence of percentages or mutable-release links.

JSON trust-boundary parsing returns deeply frozen records, and integrity assertions freeze the exact caller object after canonical equality succeeds. The contract remains server-only because canonical hashing uses Node cryptography; browser components import only its types and receive already-created packs as serialized server props. Aggregate schema limits are not permission to accept unrestricted request bodies, and the v1 GET routes accept no coverage body at all.
