# ADR 0009: Fail-Closed Voyager Geometry and Media Provenance

**Status:** Accepted for Voyager provenance foundation | **Date:** 2026-07-19

## Context

The Voyager journey already uses a frozen JPL Horizons vector response and links to official NASA, JPL, NAIF, and PDS records. That evidence is sufficient for a bounded timeline experience, but it is not an executable SPICE bundle, a physical camera-pose reconstruction, or permission to embed upstream media bytes. The repository does not contain reviewed Voyager kernel bytes, artifact digests, a meta-kernel, a CSPICE coverage report, exact media files, archived terms snapshots, or asset-level rights decisions.

NAIF's archive identifies useful Voyager filenames and encounter/refit precedence, but the restored mission kernels carry material quality caveats. Horizons and the 2022 trajectory SPK also disclose a shared Robert Jacobson solution lineage. Comparing their output can prove cross-implementation parity for an exact context; it is not an independent orbit determination. The Pale Blue Dot records identify the observation, while the current metadata does not establish the exact spacecraft-clock correlation and scan-platform attitude needed for a defensible image frustum.

## Decision

- Kernel selection and kernel execution are separate gates. A blocked selection may freeze exact official HTTPS URLs, safe filenames, Cosmography's proposed load order, stated coverage, quality, and selection rationale, but it always has `executionAllowed: false` and `releaseEligible: false`.
- A complete artifact-evidence manifest must additionally bind every artifact's exact byte length, SHA-256, unique canonical immutable object key, capture time, toolkit version, normalized meta-kernel object, coverage-report object, approved generator/parser commits, validation time, canonicalization, and manifest digest. It still has `executionAllowed: false` and `releaseEligible: false`. Selection review is a separate injected authority: an in-process reviewed-selection token must bind the exact filenames, URLs, coverage declarations, caveats, and precedence before a complete manifest is considered. Only a verifier that matches that token, recomputes the canonical manifest digest, verifies every retained object, checks the meta-kernel against the expected load order, and checks coverage against exact artifact digests/context can issue a non-serializable execution token. That token never grants publication eligibility.
- The current Voyager trajectory selection is deliberately blocked. It records `naif0012.tls`, `voyager_1.ST+1991_a54418u.merged.bsp`, `vgr1_jup230.bsp`, `vgr1_sat337.bsp`, and `vgr1.x2100.bsp` in that order. The [official Voyager BRIEF summary](https://naif.jpl.nasa.gov/pub/naif/VOYAGER/kernels/spk/aa_summaries.txt) shows that the merged and refit SPKs already contain the query-relevant Earth/planetary-barycenter/Sun segments. Their declared graph closes the early Earth/Jupiter/Saturn-to-Sun chains without adding a competing generic planetary SPK. This matters because [NAIF's kernel-priority rules](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/kernel.html#Kernel%20Priority) give later-loaded competing target/time data higher priority even when centers differ. The selection records query-relevant BRIEF coverage metadata but does not claim that bytes, byte lengths, checksums, complete local coverage, or directory timestamp timezone have been verified.
- The retained Horizons artifact is parsed as an exact, immutable reference. Target `-31`, center `10`, `ECLIPJ2000`, ICRF, TDB, AU/AU-day, geometric `NONE`, solution identity, seven epochs, and raw decimal state components must all match. Malformed markers, truncation, metadata drift, duplicate or non-monotonic epochs, and non-finite values fail closed.
- A comparison candidate must come from a separately retained and byte-verified SPICE-toolkit artifact. Its injected verifier must parse the exact retained object and return the canonical query context and numeric states; those values must exactly match the candidate before a non-serializable state token is issued. The parsed-state digest, parser/generator commits, toolkit version, kernel-manifest digest, calendar/JDTDB epoch identities, and retained object are all bound before comparison. The `1e-8 AU` position-vector and `1e-9 AU/day` velocity-vector thresholds apply only to the four post-1981 shared-lineage epochs. The three pre-1981 patched-conic/encounter comparisons are diagnostic residuals that always require scientific review; they cannot pass the same-solution parity gate. Thresholds never widen automatically and are not physical uncertainty bounds.
- Mission media has two disjoint persisted states: reference-only metadata or an exact reviewed frozen-asset record. Neither state is render authority by itself. A reference-only record can expose an official HTTPS record link and required credit text, but cannot embed, redistribute, modify, package, derive from, or render media bytes. Rendering a reviewed asset requires exact bytes, digest, canonical immutable key, product identity, derivative lineage when applicable, a named unexpired review, a non-restricted basis, explicit permission for every declared display/redistribution/modification/commercial use, and an injected evidence verifier that issues an in-process token. Evaluation requires an explicit time no earlier than admission, and the rights target must be that exact asset. Issuance never grants release eligibility.
- All five current Voyager media records remain reference-only. Free-text rights notes, public availability, a government host, or a collection-level record cannot authorize asset publication.
- Capture context has no silent visual fallback. The foundation schema intentionally exposes only a typed withheld state with reported time precision and missing-evidence reasons; there is no parseable renderable branch. Pale Blue Dot remains timeline-only until a future dedicated gate binds an admitted asset to exact capture time/clock correlation, state, attitude, SPK/CK/SCLK/LSK/FK/IK inputs, instrument/FOV, target shape, transforms, coverage, uncertainty, and a passed validation report.

## Consequences

The UI may explain the selected kernel precedence, retained Horizons oracle, validation plan, reference-only media state, and missing camera geometry without implying that blocked artifacts were executed or that media bytes were cleared. Small schemas, manifests, golden vectors, and validation receipts may live in Git; kernel and media bytes remain in quarantine or immutable bulk storage when a separately approved acquisition gate exists.

Changing the foundation atlas wording also changes its canonical release bundle. The embedded fixture's content digest, manifest digest, and seeded D1 manifest digest must therefore advance together. This is a development-fixture checkpoint, not signed production activation.

Actual artifact capture, CSPICE execution, coverage generation, media admission, physical frustum reconstruction, signing, release activation, and deployment remain separate reviewed steps. No live Horizons request or kernel/media download is part of this decision.

## Validation

Scientific-model tests prove that blocked selections cannot execute; unsafe URLs, credentials, ports, filenames, keys, extensions, center graphs, and load order fail; raw complete manifests cannot self-authorize or drift from the reviewed selection; canonical/evidence tampering fails; retained bytes cannot be detached from parsed state vectors; unverified objects cannot mint execution, state, or media-render tokens; cross-solution epochs cannot pass as shared-lineage parity; restricted, prohibited, expired, mismatched, reviewer-less, pre-admission, or byte-unverified media cannot render; and a renderable capture state is not currently representable.

Web tests parse the exact retained Horizons response, bind every raw decimal to both the public trajectory and the golden plan, exercise metadata/table mutations, verify the exact blocked kernel precedence, require one media admission per mission record, and assert that the rendered journey clearly discloses unverified bytes, pending CSPICE parity, reference-only media, and the withheld frustum.
