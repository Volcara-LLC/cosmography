# ADR 0012: Unvalidated Offline Kerr Vacuum Reference Trace

**Status:** Accepted for Kerr vacuum reference foundation | **Date:** 2026-07-19

## Context

The Black-hole Lab intentionally labels its current real-time ring as a procedural physics-visualization placeholder. The existing relativity package supplies analytic Kerr radii and a structural render-manifest schema, but that schema can describe only a future fully validated render. It is not authority, and callers can structurally assert its validation fields. Replacing the placeholder before a real null-geodesic pipeline, invariant evidence, independent comparison, renderer parity, and scientific review would turn visual plausibility into a false validation claim.

The next safe boundary therefore needs to exercise vacuum Kerr ray mechanics without producing a publishable image or weakening the existing manifest gate. It must remain deterministic, small enough for offline tests, explicit about Boyer-Lindquist coordinate limits, and unable to turn its own internally consistent hashes into render authority.

## Decision

- The first trace uses geometric `G=M=c=1` units, metric signature `-+++`, signed dimensionless spin `a/M` bounded to `|a| <= 0.999`, and Boyer-Lindquist `(t, r, theta, phi)` coordinates with `theta` defined as colatitude. It models vacuum null geodesics only.
- The camera uses an orthonormal zero-angular-momentum-observer tetrad. As a conservative first-slice policy, the request keeps it at least `1 r_g` outside the local static limit and separately outside the configured horizon guard; this is not a statement that a ZAMO is a static observer or physically requires that margin. Pixel-center rays are future-directed, locally unit-energy, and launched inward; the low-level tracer rejects reversed exterior coordinate-time orientation initially and fails closed if it appears during a path. This convention is frozen rather than silently presented as an observer past-light-cone implementation.
- Canonical momenta use `E = -p_t`, `L_z = p_phi`, and the Carter constant `Q = p_theta^2 + cos^2(theta) [L_z^2 / sin^2(theta) - a^2 E^2]`. The reduced Hamiltonian system evolves `(t, r, theta, phi, p_r, p_theta)` while keeping `p_t` and `p_phi` exact constants. It uses analytic derivatives of the inverse Kerr metric and deterministic fourth-order Runge-Kutta steps whose nominal size may be shortened at coordinate guards. A bracketed, fixed 52-iteration RK4 bisection localizes capture and finite-escape events exactly to their declared radial boundary. Momentum is never projected back onto the null shell, because that would hide integration error.
- Every accepted step updates maximum residuals for the absolute null Hamiltonian, normalized null constraint, energy, axial angular momentum, Carter constant, and the separated radial and polar potentials. Absolute Hamiltonian is diagnostic-only because its magnitude is coordinate- and momentum-scale dependent. A ray fails as `invariant-tolerance-exceeded` if normalized null residual exceeds `1e-5`, relative Carter drift exceeds `1e-5`, or either normalized separated-potential residual exceeds `1e-4`. Passing those code-owned ceilings is still not scientific validation.
- A ray can terminate only as `captured-horizon-guard`, `escaped-domain`, `coordinate-domain-exit`, `indeterminate-limit`, or `numerical-failure`. The first stops outside the Boyer-Lindquist horizon singularity and does not claim an integrated crossing. The second is an outgoing crossing of a finite code-owned radius and does not claim arrival at null infinity. The pole guard is not silently reflected, and exhaustion or numeric failure remains unresolved.
- Requests use odd row-major grids no larger than `25 x 25` or 625 pixels. A ray is limited to 12,000 accepted steps and one solver pass to two million aggregate configured steps. Report production performs one trace plus two integrity replays, for at most six million configured accepted-step evaluations; radial localization adds at most 97,500 RK4 evaluations, yielding a disclosed total bound of 6,097,500 across all three passes. Step size is bounded to `[0.005, 0.05]`, spin, camera, field of view, affine span, horizon guard, escape domain, and polar guard all have strict finite ranges, and requests that exceed any relationship or work limit fail before tracing.
- Requests, per-ray records, and reports use deterministic canonical JSON, content-derived IDs, SHA-256 checksums, strict whole-second UTC timestamps, exact row-major screen coordinates, complete-grid counts, and recomputed diagnostic summaries. Integrity regenerates the exact ZAMO seed and bounded solver result for every ray. The hashes detect inconsistent substitutions inside this contract, while `checksumAuthenticatesRecord` remains literal `false` and implementation provenance remains `caller-declared-unverified`; neither hashes nor replay authenticate authorship, scientific correctness, or the declared code commit.
- The output is `unvalidated-offline-kerr-reference-trace` and contains only a neutral finite-domain lens coordinate or horizon-guard mask for resolved rays. It contains no image pixels, disk or plasma emission, radiative transfer, frequency shift, beaming, polarization, background image, framebuffer, WebGL/GPU output, or cinematic grade.
- Every request, ray, and report retains `independentReference: "not-run"`. Scientific validation, independent validation, implementation-provenance verification, render use, production use, placeholder replacement, release eligibility, publication, and activation are literal `false`. `canUseKerrReferenceTraceForRender` always returns false. This slice does not emit `BlackHoleRenderManifest` and leaves the visible web placeholder untouched.

## Consequences

Cosmography can now run and regression-test one explicit vacuum Kerr reference path without conflating a numeric exercise with the finished BH1 scene. The package can expose coordinate conventions, critical capture/escape behavior, weak-field behavior, symmetry, bounded work, and convergence trends while retaining failure outcomes and conservation error.

This implementation is not yet an independently validated ray tracer. Its Schwarzschild critical-impact and weak-field checks are analytic same-project checks, not comparison with a separately implemented code. A later checkpoint must freeze inputs and outputs and compare them with a separately sourced and license-reviewed implementation such as GYOTO or Krang, recording exact version/commit, configuration, numeric tolerances, output hashes, and disagreement handling. A wrapper around this code or another implementation sharing its equations is not independent evidence.

Even after an independent vacuum comparison, separate work remains for adaptive integration assessment, pole/horizon coordinate strategies, GPU parity, ray bundles, background mapping, emission and radiative transfer, frequency-dependent intensity, beaming, polarization, physical parameter provenance, named-device performance, accessibility, and scientific review. Sagittarius A* spin or inclination is not supplied or inferred by this trace, and no result is equivalent to an EHT reconstruction.

Nothing in this checkpoint completes BH1, Stage 1, Stage 7, or the product. It creates no hosted resource, source request, external download, image asset, render token, release candidate, signature, publication, activation, or deployment.

## Validation

The local relativity suite currently contains 32 passing tests: 25 focused trace/contract tests plus the existing seven analytic/schema tests. The focused tests check covariant/inverse metric consistency and exterior/overflow rejection; robust ZAMO null initialization; bounded momentum scale and future time orientation; an affine-linear Schwarzschild radial ray; capture/escape bracketing around `3 sqrt(3)` with exact boundary localization; finite-distance weak-field deflection near `4M/b`; signed-spin, horizontal, and equatorial-reflection symmetries; deterministic frozen bounded requests; exact three-pass and event-localization work accounting; complete replay-verified reports; step-size classification convergence and improving Hamiltonian residuals; explicit exhaustion; nonfinite, non-null, extreme-screen, tiny-timelike, huge-momentum, and excessive-invariant failure; canonical whole-second chronology and JSON ambiguity rejection; poison-array preflight; self-consistent rehashed semantic-laundering rejection; literal-false authority; and the inability of reports or structural copies to authorize rendering or parse as a render manifest.

Those tests validate only the bounded offline implementation and internal contract described here. Independent-reference validation, GPU/WebGL parity, production performance, emission/radiative-transfer correctness, image fidelity, and release/publication readiness remain explicitly not run.
