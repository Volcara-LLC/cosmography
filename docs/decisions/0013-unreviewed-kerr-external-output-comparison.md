# ADR 0013: Unreviewed Kerr External-Output Comparison Foundation

**Status:** Accepted for unreviewed comparison foundation | **Date:** 2026-07-19

## Context

ADR 0012 established a bounded, deterministic Cosmography Kerr vacuum reference trace, but deliberately left independent comparison `not-run`. Analytic limits, symmetries, step refinement, invariant residuals, and deterministic self-replay are useful internal checks; none demonstrates agreement with a separately implemented solver. A later independent comparison also cannot be made trustworthy by accepting an arbitrary JSON file, a repository name, or a caller-set `passed` flag. The inputs, implementation identity, conventions, output bytes, mapping, tolerances, row coverage, and disagreement policy all need to be frozen before any external result is selected.

This checkpoint does not select, download, build, execute, or review an external implementation. It needs only to establish a package-local protocol that can later quarantine exact external output without letting a synthetic fixture, a same-project wrapper, a checksum, or numeric proximity become scientific or render authority.

## Decision

- A comparison plan is created only from an in-process, non-serializable verified reference bundle. The bundle can contain at most eight ordered cases and 625 rays in total. Every case binds one complete, replay-verified Kerr request and report; unresolved, coordinate-exit, exhausted, and numerical-failure reference rays are rejected from this comparison path rather than silently omitted.
- Each case has a pre-declared scientific role, unique case identifier, exact request/report IDs and checksums, canonical UTF-8 byte lengths and SHA-256 digests, grid and spin, named radial event surfaces, and an ordered binding for every pixel and ray. Structural copies of the verified bundle are rejected. The serialized plan remains data, not a capability.
- The target convention is frozen as `G=M=c=1`, signature `-+++`, signed `a/M`, Boyer-Lindquist coordinates, colatitude `theta`, covariant momentum order `(p_t,p_r,p_theta,p_phi)`, `E=-p_t`, `L_z=p_phi`, Carter `Q` rather than `K`, future-directed camera-emitted inward rays, and the ZAMO screen basis `x=+e_phi`, `y=-e_theta`, inward `=-e_r`. Momentum is compared after normalization by positive `E`; constants use `xi=L_z/E` and `eta=Q/E^2`. Azimuth retains both a canonical wrapped angle and a signed integer winding so a `2 pi` path difference cannot be laundered by wrapping.
- Before output exists, the plan freezes whether the future comparison covers only an integrator supplied with canonical initial states or covers both external camera construction and solver integration. It also freezes a full 40- or 64-hex Git commit, canonical credential-free HTTPS repository, source-archive digest and size, build/environment/run recipe digests, precision, algorithm declarations, license-text digest, and a separately versioned mapping adapter. These are caller-declared and unverified. An obvious declaration of Cosmography's own Kerr reference or repository as the external implementation is rejected, but that check is not an independence review.
- The plan fixes provisional tolerances derived only from internal convergence: `2e-12` maximum absolute initial normalized-momentum error; `2e-12` absolute `xi` error; `2e-11` absolute plus `2e-12` relative `eta` error; `2e-6` endpoint unit-sphere chord distance; `5e-5` absolute plus `1e-5` relative endpoint normalized-momentum error; and `1e-9 r_g` event-radius error. Termination class, named event surface, complete row coverage, and azimuth winding must agree exactly. Changing any tolerance or convention creates a different content-derived plan identity.
- A candidate boundary accepts only a complete normalized interchange record plus its exact bounded raw bytes. The record retains caller-declared run start, completion, raw-capture, and normalization times and enforces `plan <= start <= completion <= capture <= normalization`; the package does not verify those declarations or supply the runner. Raw and canonical normalized UTF-8 bytes receive separate length and SHA-256 bindings. The package supplies no network, filesystem, archive, decompression, build, process, worker, native parser, or external-runner capability, and recognized ZIP, gzip, 7z, RAR, bzip2, xz, and tar signatures fail closed. Synthetic exact bytes may exercise the contract in tests, but they are explicitly classified as synthetic rather than independent evidence.
- Candidate integrity requires an exact plan, implementation, mapping, case, request, report, pixel, screen, and ray binding before numeric comparison. Candidate arrays are size-preflighted before elements are inspected. Omitted, duplicated, reordered, extra, nonfinite, convention-incompatible, unresolved, or work-failure rows cannot be converted to agreement by rehashing an envelope.
- Numeric comparison is deterministic and recomputes every per-field residual, per-ray disposition, count, maximum, and aggregate result. Stable unit-sphere chord distance avoids wrapped-angle singularities. A ray can be only `within-tolerance`, `disagreed`, `inconclusive`, or `incompatible-conventions`; the aggregate can be only `within-pre-registered-tolerance`, `disagreed`, or `inconclusive`. “Within tolerance” is intentionally not named `passed`, `validated`, or `independent`.
- The comparison lifecycle discloses a conservative ceiling of five reference-solver passes: 10,000,000 configured accepted steps plus at most 162,500 fixed radial-localization RK4 evaluations, or 10,162,500 total. The plan is limited to 2 MiB canonical JSON; candidate raw output is limited to 1 MiB and canonical normalized interchange to 2 MiB. Repeated caller invocations are separate lifecycles and do not acquire authority.
- Plan, candidate, and comparison checksums are internal substitution detectors only. They do not authenticate origin, commit, runner, license, reviewer, independence, or scientific correctness. Code review, output-rights review, mapping review, environment verification, source review, and independence review remain `not-run` or literal `false`.
- Every object in this slice keeps scientific validation, independent validation, provenance verification, checksum authentication, rendering, production use, placeholder replacement, release, publication, and activation false. The comparison is not a `BlackHoleRenderManifest`, cannot issue a render capability, and leaves the visible procedural Black-hole Lab unchanged.

## Consequences

Cosmography now has a deterministic place to put future exact external solver output without deciding after seeing the result which cases, conventions, mappings, or tolerances count. Agreement and disagreement can be reported without suppressing incomplete rows or promoting a hash into evidence of authorship. The protocol also makes a negative or inconclusive comparison a retained result rather than a reason to silently adjust the benchmark.

This still is not an independent comparison. The repository, commit, license, source, build, runner, normalized mapping, and output represented by unit-test fixtures are caller declarations or synthetic bytes. A later reviewed checkpoint must choose a genuinely separate implementation, acquire permitted exact source/output bytes, retain the review evidence, run it in an isolated reproducible environment, and determine whether the mapping preserves the external program's meaning. Only then can a comparison record truthfully change from `not-run`, and even agreement within these provisional tolerances would remain one validation input rather than render or release authority.

Independent vacuum agreement will not complete BH1. GPU/WebGL parity, adaptive/numerical assessment, emission and radiative transfer, frequency shifts, intensity and polarization, physical parameter provenance, image construction, accessibility, named-device performance, and scientific review remain separate gates. No Sagittarius A* spin or viewing geometry is inferred here, and no result is equivalent to an EHT observation or reconstruction.

Nothing in this checkpoint completes a roadmap stage or the product. It creates no source request, external download, executable, image, production resource, signature, release, publication, activation, hosted project, or deployment.

## Validation

The relativity package has 53 passing tests at this checkpoint: 21 focused plan/candidate/comparison tests plus the prior 32 analytic, trace, and manifest tests. The focused suite covers deterministic plan identity, exact multi-case and row binding, causal run/capture chronology and full-commit constraints, duplicate-evidence and unresolved-case rejection, self-reference aliases, exact five-pass work totals, 1 MiB raw and 2 MiB normalized byte ceilings, recognized archive signatures, structural capability copies, exact raw/canonical byte digests, complete-grid and nested-accessor preflight, typed-array shadow accessors, semantic tampering, authority laundering, inclusive numeric boundary behavior, all four per-ray dispositions, winding/radius/termination disagreement, nonfinite and incompatible inputs, summary recomputation, deep freeze, and the invariant that every render-authority helper returns false.

Those tests validate only the bounded local protocol and its deterministic arithmetic. They use same-project reference reports and synthetic candidate bytes. No independently implemented Kerr output, source review, license review, external execution, scientific validation, GPU parity, image comparison, or production qualification has been run.
