# ADR 0020: Flight Deck Truth Classes

**Status:** Accepted for Flight Deck v1 foundation | **Date:** 2026-07-19

## Context

The foundation atlas already offered an instant camera recenter, light-speed and constant-speed calculations, and a fictional warp option in one route panel. The interface called every output an estimated journey, rendered no useful result for modes without a duration, grouped hypothetical engineering with fiction, and described a short camera animation as a journey preview. Those labels collapse map interaction, physical limits, historical data, engineering assumptions, and storytelling into one misleading transport claim.

Cosmography needs an inviting way to compare cosmic distance and time without implying that a camera transition is travel, that a light signal is a ship, that Voyager 1 is an available transport, that an assumed fusion spacecraft exists, or that warp has a scientific duration. The comparison must also preserve the immutable foundation release rather than retroactively adding fields to its hash-bound navigation records.

## Decision

- Flight Deck v1 has exactly five ordered modes: `instant`, `light`, `voyager`, `fusion`, and `warp`. Their truth classes are respectively `navigation`, `physical-limit`, `historical-comparison`, `hypothetical-physical`, and `fictional-only`. The classes are mutually distinct in the schema, interface, API, and saved assumptions.
- Map jump is semantic navigation only and has no physical duration. Light signal is vacuum light-time over the stored source-distance input and is not a spacecraft or trip plan. Voyager is a counterfactual constant-speed comparison, not the spacecraft's actual trajectory, telemetry, or an available transport. Fusion is a hypothetical physical scenario at a declared constant `0.1c`, not fiction and not an available spacecraft. Warp is fictional presentation only and emits no scientific duration.
- The Voyager comparison is pinned to the retained JPL Horizons vector fixture at `1990-02-14 00:00:00.0000 TDB`, centered on the Sun in Ecliptic J2000 / ICRF with geometric correction `NONE` and `AU-D` output. Its derived speed is `17.882843512181083 km/s`, or `0.000059650745157108265 c`. This frozen epoch is used only as a constant-speed reference; it creates no trajectory, telemetry, current-state, mission-plan, or transport claim.
- Duration is either a derived nonnegative value or `null`. Map jump and warp always use `null`; physical comparisons also use `null` when the destination lacks a stored source distance. A missing result is displayed as a named state, never as blank output. Constant-speed results are stored distance divided by the selected fixed speed and omit acceleration, deceleration, energy, route geometry, mission constraints, and traveler-frame time.
- Camera recentering is interface feedback, not elapsed travel. Selecting a mode changes the comparison only and causes no automatic movement. The explicit action is named **Recenter map**, and the interface keeps the non-journey boundary visible.
- Flight Deck URLs pin one canonical destination slug, exact mode, exact foundation release, and valid appearance. Duplicate, missing, extra, stale, unknown, tour-mixed, or otherwise ambiguous query state fails closed. Known legacy entity IDs redirect to the canonical slug. Opening or changing Flight Deck rewrites the canonical state; closing it removes `travel`; a shared URL includes the mode only while the deck is open.
- A separate `foundation-flight-deck-distance-v1` projection binds every numeric comparison input to the exact foundation release ID, manifest SHA-256, content SHA-256, and its destination-record sources without changing the frozen navigation bundle digest. It explicitly says that field-level ingestion lineage is not yet available and that the number is not a route length. The zero-distance Solar System entry is an observer-origin definition. The interface must call the linked records **destination record sources**, not exact distance sources.
- Saved comparisons remain private and account-isolated in the existing D1 route tables; Flight Deck v1 requires no migration. The strict request pins the exact release and private visibility. Stored assumptions distinguish mode-source records from destination-record sources, retain the result kind and nullable duration, repeat literal-false journey/trajectory/telemetry/available-vehicle claims, and include the exact frozen Voyager reference only for the Voyager mode.
- No Flight Deck record authorizes a spacecraft, mission, trajectory, telemetry stream, scientific validation, publication, release activation, or deployment. No LLM, narration, grading, live upstream request, hosted resource, or production transport is introduced by this decision.

## Consequences

Users can compare scale with clear scientific boundaries while keeping playful fiction available as fiction. Canonical deep links can reopen the same release, destination, appearance, and comparison, and private saves retain enough assumptions to explain their result later. The frozen navigation release remains unchanged because the additional distance-binding projection is explicitly derivative.

The outputs are educational comparisons, not route planning. The foundation distance inputs still need field-level ingest lineage, uncertainty models, and reviewed source updates in a future exact release. The historical Voyager speed is one chosen epoch, not a universal cruise speed or a claim about the spacecraft's full mission. Relativistic traveler-frame calculations, propulsion feasibility, acceleration profiles, route geometry, resource estimates, and actual mission design remain separate future work.

## Validation

Strict model tests pin the five-mode order, truth classes, exact disclosures, nullable-result rules, speed arithmetic, duration formatting, frozen Horizons metadata/vector/checksum, deep immutability, and drift rejection. Projection tests bind every numeric foundation destination exactly once, preserve ordered destination-record sources, reject source/distance/release/origin drift, and retain literal-false lineage and straight-line-route claims. Built-worker tests cover canonical deep links and fail-closed malformed state. Account tests cover every mode, null-duration persistence, exact Voyager assumptions, non-fictional fusion, strict input, private ownership, atomic rollback, and no-store responses. Rendered, keyboard, narrow-viewport, contrast, label-floor, touch-target, and bundle tests verify the accessible daylight panel and confirm that Flight Deck code and styles remain outside the initial home preload graph.
