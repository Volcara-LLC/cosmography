# ADR 0015: Package-Only Kerr Execution-Receipt Verification and Quarantined Output Admission

**Status:** Accepted for package-only receipt/admission foundation | **Date:** 2026-07-19

## Context

ADR 0014 ends at a process-issued handoff that has been claimed immediately before a future isolated runner would act. Claiming that handoff is intentionally not evidence that a runner received it, enforced its reviewed sandbox, executed the reviewed binary, or produced any bytes. ADR 0013's existing external-output candidate is also intentionally caller-declared and keeps execution verification false. Neither object can be relabeled or rehashed into execution evidence.

The active checkpoint needs a fail-closed place to verify a future runner receipt and admit its exact output to quarantine without adding a runner to this package. The receipt must remain bound to the answer-blinded request: neither the external solver nor its normalizer may receive Cosmography reference outcomes, result identifiers or checksums, provisional tolerances, or comparison summaries. Receipt verification and byte admission must also remain narrower than implementation independence, mapping correctness, numeric comparison, scientific validation, or render authority.

## Decision

- Receipt admission begins with the exact process-issued runner handoff after its one permitted claim. A strict canonical receipt binds the handoff, authorization, execution request, reviewed selection, attempt nonce, audience, plan and blinded-input identities, source archive and tree, executable, build/environment/run recipes, invocation, deterministic environment, sandbox prohibitions, and resource ceilings. A structural copy, a receipt for another attempt, or a rehashed envelope cannot cross this boundary.
- The receipt records runner-reported start, completion, output-capture, normalization, and issuance times; exit status and signal state; policy-violation and truncation state; measured CPU, wall time, memory, process, writable-byte, stdout, stderr, and output usage; and exact raw and canonical normalized artifact descriptors. Chronology must follow the claimed handoff and remain within the reviewed request's validity and limits. A nonzero exit, signal, timeout, network use, sandbox violation, truncation, missing artifact, or exceeded ceiling remains a failed receipt and cannot admit output.
- Receipt authenticity is an injected trust boundary, not a caller boolean or a package checksum. An exported strict preparation API builds and canonicalizes the runner-known statement from only the released handoff plus runner result bindings; package-private claim, selection, request, and plan metadata are excluded. Receipt creation replays that same API and binds its digest plus the exact detached signature-envelope bytes, length, and digest. The verifier receives the frozen verification subject, frozen receipt, and a detached copy of those exact envelope bytes, then must return one strict structured receipt binding the receipt, claim, runner identity, runner grant and key, runner-key purpose, attestation-policy identity, audience and purpose, signature verification, current validity and revocation decision, and explicit check time. It must also assert the attestation payload, exact claim, execution profile, sandbox evidence, clean exit, resource limits, raw bytes, and normalized bytes, through `verifierAssertsEvidenceNotSynthetic` and `verifierAssertsEvidenceNotCallerDeclared`. The runner key must be distinct from all three selection-review keys. These remain assertions from the injected verifier rather than facts independently established by this package. Thrown, malformed, stale, mismatched, revoked, or negative verifier results fail closed. This package supplies no key registry, signature service, authoritative clock, attestation service, or durable audit log.
- Raw output remains one bounded, uncompressed exact byte sequence. Canonical normalized output is bound separately to exact UTF-8 bytes and deterministic canonicalization. Both byte arrays are copied and size-preflighted before caller-controlled rows are inspected; their byte lengths and SHA-256 digests must exactly match the receipt and the reconstructed admission record. Recognized archive signatures remain rejected, and checksums remain substitution detectors rather than proof of origin.
- Normalized runner output uses a strict answer-blinded row schema with exactly one row per blinded ray in blinded plan order. Rows carry bounded case/ray ordinals; pixel index and coordinates; runner-declared screen coordinates; and the external program's normalized initial values, constants, termination, and optional endpoint, plus package-derived row identity/binding fields. They cannot contain Cosmography reference case, request, report, or ray identities; reference outcomes or endpoints; reference checksums; tolerances; residuals; dispositions; or summaries. Integrator-only screen coordinates must equal the already blinded input. Camera-and-solver screen coordinates are runner-declared output whose independent derivation this package cannot prove. Package-owned admission may associate verified rows with the full plan only after receipt and exact-byte verification.
- Solver execution and normalization remain distinct evidence concerns even though this checkpoint models one combined receipt. The receipt binds the overall reviewed executable, `normalizerSourceSha256`, exact raw-input digest, blinded ordinal mapping, and exact canonical normalized output identity, checksum, bytes, length, and digest. It does not bind a separate normalizer executable or prove mapping semantics; mapping correctness remains false until a later mapping-review gate establishes it.
- One claimed handoff can attempt receipt verification once, and one verified receipt can attempt output admission once. Each attempt is burned before its asynchronous current-grant check, so a failed check cannot be retried with a changed time or envelope. A successful admission issues an immutable, process-local, non-serializable capability recorded by object identity and bound to the exact receipt, raw bytes, normalized bytes, normalized rows, and plan. Structural copies and replay under another plan fail. Consumption by a future comparison-review gate is not implemented in this checkpoint; a serialized receipt or admitted-output record alone is never capability authority.
- The narrow verified state is `kerr-execution-receipt-binding-verified-in-process-for-quarantine`, followed by `receipt-verified-kerr-output-admitted-to-process-local-quarantine`. Admission makes only `comparisonReviewPreparationAllowed` true. It propagates `attestationEvidenceStatus: injected-verifier-asserted-not-package-authenticated` and `injectedVerifierAuthorityAuthenticatedByPackage: false`, and keeps `executionVerified`, `candidateAdmissionAllowed`, `comparisonAllowed`, mapping correctness, implementation provenance, independence, scientific validation, independent validation, rendering, production use, placeholder replacement, release eligibility, publication, and activation false, with `independentReference` still `not-run`. A verifier-accepted receipt does not mean that this package observed execution, authenticated the verifier, established that the executable was derived from the declared source, or found numeric agreement.
- This package performs no network or filesystem I/O, source acquisition, download, archive extraction, dependency installation, build, shell, subprocess, worker, dynamic or native loading, sandboxing, runner operation, output capture, signing, or external execution. Unit tests exercise only synthetic in-memory handoffs, receipt declarations, verifier assertions, and bytes. The receipt declares `claimedEvidenceClass: runner-declared-isolated-execution-receipt-awaiting-verification`, while `verifierAssertsEvidenceNotSynthetic` and `verifierAssertsEvidenceNotCallerDeclared` remain injected trust-boundary assertions. The controlling package truths remain `injectedVerifierAuthorityAuthenticatedByPackage: false` and `realExternalExecutionEstablishedByPackage: false`. No real execution receipt, runner attestation, raw output, normalized output, or admitted external candidate exists.

## Consequences

The contract can make a future output traceable to one reviewed, blinded execution intent without allowing a caller-supplied receipt, checksum, or normalized row set to become live authority. Exact raw/canonical byte separation prevents later normalization changes from being hidden behind the solver artifact, while one-use process identity prevents a test fixture or copied admission record from being replayed into another comparison.

This checkpoint still cannot prove that execution happened. Its structured verifier is an injected, package-unauthenticated trust boundary, its resource measurements and sandbox state are runner reports, and its process-local capabilities disappear on restart. A later durable ledger must authenticate runner and reviewer identities, key purpose, validity and revocation at authoritative times, retain immutable receipt, signature-envelope, and artifact bytes, and atomically prevent replay across workers. A separately reviewed isolated runner must acquire permitted source, verify source-to-executable lineage, build reproducibly, execute the blinded input, enforce the sandbox, sign the canonical runner-known statement, and emit the real attested receipt.

After that, mapping review, exact candidate reconstruction, independent numeric comparison, scientific adjudication of agreement or disagreement, GPU/WebGL parity, emission and radiative transfer, image production, named-device performance, accessibility, and release governance remain separate gates. Nothing in this checkpoint completes BH1, a roadmap stage, or the product, and it changes nothing in the visible procedural Black-hole Lab.

## Validation

Acceptance for this checkpoint requires synthetic package tests covering exact claimed-handoff and attempt binding; causal receipt chronology; structured runner-verifier receipts; runner/reviewer key separation; failed exit, signal, truncation, network, sandbox, and resource-limit states; exact raw and canonical normalized byte binding; archive and size rejection; complete answer-blinded row order; forbidden reference-field laundering; poison-object and typed-array preflight; semantic tampering despite recomputed checksums; structural-copy forgery; one verification attempt per claim and one admission attempt per verified receipt; deep freezing; and literal-false comparison, scientific, render, release, publication, and activation authority.

Those tests can validate only the package contract. They use synthetic runner receipts and bytes and cannot validate a real repository, source tree, executable, build, environment, normalizer, license, reviewer, runner, attestation, output, independent comparison, or scientific result.

The accepted checkpoint passes the complete relativity package check with 97 tests, including 27 authorization/claimed-handoff cases and 17 receipt/admission cases. The focused authorization-plus-receipt run passes all 44 cases. TypeScript compilation and the production dependency audit also pass with zero reported vulnerabilities for this package.
