# ADR 0014: Package-Only Kerr External Selection and Execution Authorization

**Status:** Accepted for package-only authorization foundation | **Date:** 2026-07-19

## Context

ADR 0013 froze a bounded comparison plan and an exact-byte quarantine boundary before any external Kerr result exists. That plan intentionally contains the Cosmography reference outcomes, report and ray bindings, and pre-registered tolerances needed for later comparison. Giving the complete plan to a purportedly independent solver or its normalizer would disclose the answers and allow a program to echo or tune itself to the reference. A repository URL, source digest, license label, approval string, or caller-set boolean would not prevent that laundering and would not prove independent implementation, reviewed rights, a safe environment, or an observed execution.

The next safe slice therefore needs to model selection review and an execution-request authorization boundary without acquiring or running anything. It must disclose only a blinded input to a future external program, require independent decisions from the three relevant review disciplines, reject copied or replayed capabilities, and remain unable to convert authorization into evidence that an execution or comparison occurred.

## Decision

- A deterministic blinded run input is derived for one exact comparison plan and scope. It contains only the external program inputs needed for the declared `integrator-only` or `camera-and-solver` task, plus ordinal bindings needed to associate future output. It excludes Cosmography reference identifiers, endpoints and outcomes, report and ray checksums, comparison residuals, provisional tolerances, aggregate results, and every other answer-bearing field. A camera-and-solver input also excludes Cosmography-derived screen coordinates so the external camera construction remains under comparison. A future solver and mapping process must receive this blinded artifact rather than the complete comparison plan.
- Selection review binds one canonical subject containing the exact plan identity, blinded-input identity, external implementation and source-archive declarations, mapping declaration, full source and mapping commits, source/dependency/submodule/LFS/SBOM evidence, independence and rights-review packages, explicit false declarations for known Cosmography tree/dependency/fixture/mirror lineage matches, license evidence, build and environment manifests, structured executable-plus-arguments recipe, sandbox prohibitions, and fixed resource/output ceilings. Public SHA-256 values remain internal binding checks; they do not authenticate the declared source, reviewer, license, or environment.
- Exactly three review roles are required: scientific independence, security/execution, and license/output rights. There is exactly one accepted decision for each role, and the reviewer, role-grant, and key identities must each be distinct across the three decisions. A role cannot substitute for another, one identity cannot satisfy two roles, an unknown or duplicate role fails closed, and every decision binds the same canonical subject and occurs after that subject is frozen. Injected verification receipts must bind those exact identities, the subject digest, signature and role-grant checks, revocation state, and a causal check time. These records model an in-process trusted verification boundary but do not supply a durable identity, signature, role-grant, revocation, or audit service.
- A reviewed-selection capability is issued only after the complete three-role record and its exact subject bindings pass. It is immutable, process-local, non-serializable authority recorded by object identity rather than by a copyable property. Structural clones, reconstructed objects, checksums, and serialized review records cannot cross the boundary. The capability permits only creation of a correspondingly bound execution request; it does not permit source acquisition, building, execution, comparison, rendering, or publication.
- A separate execution-authorization capability is derived from that exact issued selection and exact blinded request. One request cannot be reauthorized under a different check time. Current role grants, keys, expiry, and revocation are rechecked at authorization and again at consumption. Consumption retires the capability before any asynchronous verifier can race, and the resulting runner-safe handoff is itself process-issued, carries the request expiry, and rejects structural copies. It must be claimed once immediately before future runner use; claiming burns it before another expiry/revocation check can await. Process restart or loading another package instance loses every capability rather than silently recreating it. These objects are narrow authorization for a future isolated executor handoff, not evidence that a runner received one or that execution happened.
- The future command boundary is declarative and fail closed: executable identity and arguments are structured rather than represented by a shell command; working directory, a small code-owned environment name/value allowlist, network prohibition, input/output bindings, and CPU, wall-time, memory, process, filesystem, and byte ceilings are fixed by the reviewed subject. Inherited environment, secrets, proxy variables, dynamic preload controls, path lookup, and shell execution are forbidden. Changing the implementation, source, mapping, recipe, environment, blinded input, limit, time, or plan requires a new review and capability.
- This package supplies no network or filesystem I/O, repository client, downloader, archive extraction, dependency installation, build system, shell, subprocess, worker, dynamic loader, native bridge, container runtime, sandbox, or external runner. It neither reads the declared source archive nor observes an executable. Tests may use synthetic frozen review records and in-memory declarations only.
- No real external implementation has been selected. No source, mapping, dependency graph, license, output right, build recipe, environment, or command has received a real review; no real execution request has been authorized, no execution has been observed, and no external raw or normalized output has been produced by this slice. The existing caller-declared and synthetic candidate path is not upgraded into reviewed evidence.
- Review or authorization cannot establish implementation provenance, independence, scientific agreement, execution verification, checksum authenticity, or mapping correctness. Scientific validation, independent validation, rendering, production use, placeholder replacement, release eligibility, publication, and activation remain literal `false`. The visible procedural Black-hole Lab remains unchanged.

## Consequences

Cosmography can now test the shape of a least-authority handoff before introducing an untrusted external code path. The explicit blinded artifact prevents the comparison reference from becoming solver input, three-role separation makes the review responsibilities visible, and process-local one-use capabilities prevent a schema-valid object or replayed token from posing as live authorization within one package instance.

This is not a durable governance or execution system. Process-local object identity cannot cross a service boundary, survive restart, prove who reviewed a subject, or coordinate atomic one-use consumption among workers. A later durable authorization ledger must bind signed identities and role grants to the canonical subject, apply validity and revocation at an authoritative check time, enforce audience and attempt nonces, and atomically consume execution authority.

A separate isolated-runner gate must then acquire permitted exact source bytes, verify complete source/dependency and license evidence, build in a reproducible sandbox, execute only the blinded input under the reviewed limits, and issue an independently verifiable receipt binding the consumed authorization, executable, environment, command, timestamps, exit status, sandbox policy, and exact raw output bytes. Mapping review, exact normalized-output reconstruction, independent scientific comparison, renderer parity, image production, performance qualification, and release governance remain later gates.

Nothing in this checkpoint completes BH1, a roadmap stage, or the product. It performs no external I/O, source request, download, build, execution, comparison, render, signing, publication, activation, hosted-resource creation, or deployment.

## Validation

The package authorization tests use synthetic declarations only. They cover deterministic blinded inputs and subject binding; exclusion of reference outcomes, tolerances, and checksums from solver-visible data; exact three-role coverage and distinct reviewers; chronology and substitution rejection; structural-copy forgery; one-use consumption and replay rejection; and the invariant that selection and authorization leave execution verification plus every downstream scientific, render, release, publication, and activation authority false.

Those tests validate only an in-process contract. They do not validate an external repository, source tree, dependency graph, license, reviewer identity, environment, executable, runner, output, independent comparison, or scientific result.
